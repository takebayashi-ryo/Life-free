# Life free は何のアプリか（再定義 / 2026-09）

前提は [`positioning.md`](positioning.md)。こちらは「では具体的に何を作るのか」。

---

## 一言でいうと

> **子どもの生年を入れると、家計が一番きつくなる年を教えてくれるアプリ。**

記録アプリではない。シミュレーターでもない。**ピーク年を名指しするアプリ**。

---

## なぜ「ピーク年」なのか

教育費の話はいつも**総額**で語られる。「大学まで1,000万」「2,000万」。
だが総額は行動を変えない。18年後に1,000万と言われても何もできない。

効くのは**いつ**。

```
✗ 「教育費は総額1,800万円かかります」   → 遠い。他人事。
✓ 「2044年が一番きつい。上の子が大学1年、
    下の子が高3。その年だけで年間270万円」 → 具体。自分事。
```

しかもピークは**重なり**で決まる。子が2人いれば、上の大学と下の高校が重なる年がある。
総額の話ではこの山が見えない。**この山こそが家計を壊す。**

そして0〜7歳の親は、この山が**まだ10年以上先**にある。だから間に合う。
これが「7歳で切る」理由と一本の線でつながる。

---

## 3つの層

| 層 | 何をする | いつ触る | 入力 |
|---|---|---|---|
| **① 診断** | ピーク年を出す | 初回30秒 | 子の生年 / 今の資産 / 月の積立 |
| **② 計画** | 山を越える手を打つ | 診断の直後 | 進路・イベント・積立額の調整 |
| **③ 記録** | 予測の精度を上げる | 月末に1回 | 実際の残高 |

**①だけで価値が完結していること**が絶対条件。
②③は「もっと知りたくなった人」だけが進む。

現状のアプリは③が入口になっている。**順番が逆。**

---

## ① 診断 — 30秒で出す

### 入力（3つだけ）

```
子どもの生まれた年   2021年  （＋もう一人）
今の貯蓄＋投資       450万円
毎月の積立           8万円
```

進路は既定値（高校まで公立 / 大学は私立文系 / 自宅通学）で先に答えを出す。
あとから変えられる。**最初に設定させない。**

### 出力

```
一番きついのは 2044年

  長男 18歳・大学1年      118万円
  次男 15歳・高校1年        60万円
  ────────────────────────
  その年の教育費         年 178万円

このままだと、2046年に資産が 120万円まで減ります。
月の積立をあと 2.4万円 増やせば、底が 500万円で止まります。
```

出すのは3つだけ。**いつ / いくら / どうすれば足りるか。**
グラフはその下。数字の羅列は出さない。

### 計算の骨格

- 子の生年 → 各年の学年（4/1時点の年齢ベース。早生まれは概算）
- 学年 → 年間教育費（下表）
- ピーク年 = 全員分の教育費合計が最大になる年
- 資産推移 = `A(y+1) = (A(y) − 教育費(y)) × (1 + 年率) + 月積立 × 12`
- 不足額 = 底がマイナスなら、底が0を割らない積立額を逆算

### 教育費の基準値（年額・概算）

出典: 文部科学省「子供の学習費調査」(令和3年度) / 日本政策金融公庫「教育費負担の実態調査」

| 段階 | 公立・国立 | 私立 |
|---|---|---|
| 幼稚園・保育園（3〜5歳） | 約10万 | 約30万 |
| 小学校 | 約35万 | 約167万 |
| 中学校 | 約54万 | 約144万 |
| 高校 | 約60万 | 約103万 |
| 大学 初年度 | 約82万 | 文系 約118万 / 理系 約156万 |
| 大学 2年目以降 | 約54万 | 文系 約95万 / 理系 約132万 |
| 下宿する場合 | ＋年100万 | ＋年100万 |

**注意して扱うこと**

- 0〜2歳の保育料は世帯収入で大きく変わるため**含めない**（診断では0扱い）
- 3〜5歳は幼児教育無償化により保育料は無料。給食費・行事費のみ
- 高校は就学支援金を織り込んだ実質負担に近い値
- **すべて概算。画面にも必ず「概算です」と出す。** 断言すると信頼を失う

## ② 計画 — 山を越える手

診断で山が見えたら、次は打ち手。既存のライフプラン・タイムラインがここに入る。

| 打ち手 | アプリでの操作 |
|---|---|
| 積立を増やす | 月額スライダー。底がどう動くか即座に見える |
| 進路の想定を変える | 国立 / 私立、自宅 / 下宿 |
| 収入イベントを入れる | 昇進・復職・児童手当 |
| 支出イベントを入れる | 住宅購入、車の買い替え |

**現状の「基本の投資余力」という言葉は捨てる。** 説明が要る時点で負け。
「毎月いくら積み立てるか」で十分。

---

## ③ 記録 — 精度を上げる手段

月末スナップショットはこのアプリの強み。ただし**役割を変える**。

```
✗ 記録をつけるためのアプリ
✓ 「あなたは実際に月18万積み立てている」という事実を
  予測に流し込むための入力
```

記録が2ヶ月たまったら、診断の「月の積立」欄に実績値が入る。
これが競合との決定的な差になる。他のシミュレーターは**想像の数字**しか使えない。

記録画面は残すが、**入口ではなくなる。**

## 画面構成（あるべき姿）

| 現状 | あるべき |
|---|---|
| ホーム / 記録 / 予測 / 分析 / 設定（5タブ） | **ピーク / 計画 / 記録 / 設定（4タブ）** |
| 起動 → 総資産 | 起動 → **ピーク年と不足額** |
| 初回 → 設定9項目 | 初回 → **入力3つ** |

- 分析タブは記録タブに統合（グラフは記録の中で十分）
- ホームは「ピーク」に置き換える。総資産は2番目の情報

## やらないと決めたこと

| | 理由 |
|---|---|
| 銀行・カード連携 | マネフォの土俵。使用日ベースの記録は最初から捨てている |
| 日々の家計簿 | 月末スナップショットで足りる。それが差別化 |
| 老後2,000万問題 | 対象年齢が違う。話を広げると刺さらなくなる |
| 保険の提案 | 無料FP相談との違いがこれ。**売らないことが価値** |

## 進める順番

```
1. LPを作る（＝①診断を先にLP上で動くものとして作る）   ← いまここ
2. 知人に見せる / コミュニティ / 広告5,000円
3. 反応あり → ①をアプリ本体の入口として実装。②③を後ろに下げる
4. その先 → 認証・データ分離・課金・iOS化
```

**3より先には、2の結果が出るまで進まない。**
LP上で診断が動けば、それはそのままアプリ本体の①のプロトタイプになる。
捨てる作業にはならない。
